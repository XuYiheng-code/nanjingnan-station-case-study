# 南京南站案例智能体 · MVP 开发规划

> 目标：在选题阶段（→7/10）做出一个**能现场演示、可溯源、不胡编**的最小可用原型，
> 作为选题报告里"创新作品已有原型"的实证，并为入围后扩展为完整"案例创新奖"作品打底。
> 设计原则：**最大化复用 `aifit_demo` 与 `interview-robot` 既有骨架，最小化新写代码。**

---

## 一、MVP 范围界定（克制是关键）

完整智能体有三内核（可溯源问答 / 多主体推演 / 数据看板）。**MVP 只做内核1 + 内核2 的极简版**，把"很能打"的差异化点先立起来，看板留到入围后。

| 内核 | 完整版 | **MVP 版（7/10前）** |
|---|---|---|
| ① 可溯源 RAG 问答 | 全语料、多轮、引用高亮 | ✅ **做**：单轮问答 + 给出处（语料片段+来源文件名） |
| ② 多主体角色推演 | 政府/平台/市民三方自由博弈 | ✅ **做极简**：1 个两难场景（执法权禁区"违停处置"）+ 用户扮演交控万物做 2–3 步决策 + AI 推演后果 |
| ③ 治理数据看板 | 工单闭环/算法分布/制度边界可视化 | ⛔ 暂不做，入围后再加 |

**MVP 验收标准（一句话）**：评委打开网页 → 问"南京南站违停怎么管？" → 智能体基于真实调研语料作答并标出处 → 点"进入推演" → 扮演交控万物，在"只能巡查劝导不能罚"的约束下做决策 → 看到交易成本/合法性后果反馈 → 收束到"有限的整体性治理"。**全程 < 3 分钟跑通。**

| 需要的能力 | 直接复用 | 改动量 |
|---|---|---|
| LLM 调用（超时/重试/json 模式） | `aifit_demo/llm_client.py` | 改 env 指向 Claude；几乎零改 |

> 结论：**没有一处需要从零造轮子。** MVP 工作量集中在"语料工程 + 两段 prompt 设计 + 接线"。

## 三、语料工程（智能体的护城河，最先做）

这是别队拿不到的一手资产，也是"反 AIGC 编造"的合规保障。

**数据源（项目内已有）：**
- `对交控万物的调研资料：录音与文本/`：南京南站调研录音转录、南京交通集团访谈转录、调研问题反馈
- `万物云资料/`：灵石 AIoT 产品手册、万物云企业简介、城市更新运营
- 政策文本：`国务院"人工智能+"行动意见`、`南京市铁路南京南站地区综合管理办法`、`推动城市高质量发展的意见`
- 案例正文/分析过程文本：`过程文本/`、`26.3.24 基础文本内容.docx`

**处理流水线（4 步，半天可跑通）：**
1. **抽取**：docx/pdf → 纯文本（用 python-docx / pdftotext，项目里已验证可用）。
2. **清洗 + 切片**：按语义段切 300–600 字 chunk，**每片带元数据**：`{来源文件, 类型(访谈/政策/产品/分析), 主体, 段落序号}`。
3. **入库**：沿用 aifit knowledge 的 JSON/向量工件模式建 `nanjing_south_corpus.json`；MVP 阶段可先用**关键词 + 向量混合检索**（小语料够用，不必上重型向量库）。
4. **溯源契约**：每条检索结果必须返回 `text + source`，前端展示"据《XX访谈》"——**回答必带出处，查不到就说"语料中暂无"**（硬约束，杜绝幻觉）。

## 四、两段核心 Prompt（MVP 的"灵魂"）

**Prompt-A ｜ 可溯源问答（系统提示要点）**
- 角色：南京南站治理案例研究助手。
- 铁律：**只依据检索到的语料片段作答，每个关键论断后标注来源**；语料无依据时明确说"暂无语料支撑"，**禁止编造数据/情节**。
- 风格：先给结论，再给机制（可挂"技术—组织—制度"框架），最后给出处。

**Prompt-B ｜ 多主体决策推演（MVP 单场景：违停处置）**
- 场景设定（喂给模型的背景）：南京南站站区违停，交控万物**无行政执法权**，只能"巡查—劝导—上报"，罚款须交公安交管。
- 用户身份：交控万物运营负责人。
- 交互：用户每做一个决策（如"加密巡查"/"直接劝离"/"上报交警联合执法"），模型输出三段反馈：
  1. **效率视角**：这一步对交易成本（搜寻/协调/监督）的影响；
  2. **合法性视角**：是否触碰执法权/数据/属地三重刚性边界；
  3. **后果与点评**：推演结果，并在 2–3 步后收束到"这正是**有限的整体性治理**——平台能整合操作，但整合不了法定权力"。
- 价值：把命题3的抽象机制变成评委**可玩、可感**的体验。

## 五、技术选型（务实，能在赛程内交付）

- **后端**：Python（直接用 aifit 那套，零迁移成本）。
- **前端**：复用 interview-robot 的 Next.js chat（已有 ASR，可支持语音提问，决赛加分）。
- **模型**：`llm_client.py` 改 env 切到 **Claude Opus 4.x**（角色扮演与机制推演质量最高）；问答检索部分模型可灵活。
- **部署**：MVP 本地 `demo_up.sh` 跑通即可（aifit 已有 demo_up/demo_down 脚本）；决赛前再做离线兜底版。
- **合规**：智能体属"创新作品"独立计；但凡其产出要写进正文，必须人工复核 + AIGC 红标。
