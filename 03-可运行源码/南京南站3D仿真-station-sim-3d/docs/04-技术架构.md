# 技术架构

## 前端

- React 19 + TypeScript。
- Three.js 与 React Three Fiber 负责三维渲染。
- Vite 负责本地开发和构建。
- 首版不依赖地图底图，也不上传任何内部数据。

## 模块边界

```text
公开事实 / 案例材料 / 推演参数
              │
              ▼
        数据校验与口径标记
              │
       ┌──────┴──────┐
       ▼             ▼
   客流模拟器      事件状态机
       │             │
       └──────┬──────┘
              ▼
        三维场景与二维面板
```

三维网格只负责空间表达。客流、部门、事件和指标存放在独立数据文件中，后续可以替换模型或数据源。

## 性能策略

- 客流使用 `InstancedMesh`，不为每个粒子创建独立 React 组件。
- 使用固定随机种子，保证每次演示的结果一致。
- 桌面端首版目标为 1,500–2,000 个可见代理；移动端自动降到 400–600 个。
- 使用按需渲染、分级像素比、简化阴影和几何 LOD。
- 浏览器不支持 WebGL 时显示二维站区与职责表。

## 数据接口预留

首版读取静态 JSON。后续可以接入 CSV 或 API，但每个字段都必须带 `sourceType`、`timeRange`、`metricDefinition` 和 `updatedAt`。没有这些元数据的数字不进入默认界面。

## 隐私与安全

真实数据进入项目前先做聚合和脱敏。界面以 15 分钟或更粗粒度展示客流，不显示可识别个人的轨迹。内部点位、排班和处置预案不进入公开版本。
