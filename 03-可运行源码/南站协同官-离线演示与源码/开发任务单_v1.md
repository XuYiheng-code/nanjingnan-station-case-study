# 南站协同官：开发任务单 v1

任务按“先把不可越过的边界写成可运行约束，再做界面”的顺序安排。P0 完成后即可进入编码；P1 不得阻塞演示主线。

## P0：最小可演示链路

| 编号 | 任务 | 完成条件 | 依赖 |
| --- | --- | --- | --- |
| P0-01 | 冻结展示边界 | 首页、接口返回和日志均显示“案例教学与模拟推演”；没有外部派单代码。 | 无 |
| P0-02 | 建立数据加载器 | 能读取并校验 `source-registry`、`evidence-cards`、`authority-rules`、SC-01 与六份 Schema。 | P0-01 |
| P0-03 | 建立证据卡库 | 至少 12 张经研究组批准的证据卡，其中公开制度、脱敏访谈、模拟设定分别有明确标识。 | P0-02 |
| P0-04 | 编写 SC-01 和权责规则 | SC-01 包含一个事件、三个角色、至少三条规则和一个升级分支。 | P0-02 |
| P0-05 | 完成确定性卡片生成 | 不调用模型，也可从事件、证据和规则生成 `pending_human_confirmation` 卡片。 | P0-03、P0-04 |
| P0-06 | 完成校验器 | 缺来源、缺人工闸门、越权动作、规则未知四类输入都不能生成可确认卡片。 | P0-05 |
| P0-07 | 完成 Flask API | 实现工程设计中的五个端点；请求和响应通过 Schema 测试。 | P0-05、P0-06 |
| P0-08 | 完成演示工作台 | 展示情景、证据、权责、卡片和确认按钮；无“发送”“执行”等误导性按钮。 | P0-07 |
| P0-09 | 本地审计日志 | 每次草稿和人工决定写入本地 JSONL；日志保留时间、角色、原因和卡片版本。 | P0-07 |
| P0-10 | 回归测试 | `golden-cases.json` 全部通过；特别是所有越权反例必须转人工或升级。 | P0-06、P0-07 |

## P1：提高交互和可解释性

| 编号 | 任务 | 完成条件 | 依赖 |
| --- | --- | --- | --- |
| P1-01 | 可溯源检索 | 能按关键词和元数据筛选证据卡，前端展开来源定位。 | P0-03 |
| P1-02 | 受限模型起草 | 模型只输出 Schema 允许字段；失败时稳定回退模板卡。 | P0-06、P1-01 |
| P1-03 | 角色视图 | 同一事件按现场主管、综管办、铁路联络人展示不同的待确认事项，但不改变底层规则。 | P0-08 |
| P1-04 | 复盘页 | 根据审计日志生成“已确认／被拒绝／已升级”的模拟复盘，不计算真实绩效。 | P0-09 |
| P1-05 | 语音输入 | 仅把语音转为文本，仍走同一套规则与人工确认流程。 | P0-07 |

## 暂不进入本轮的工作

- 对接真实摄像头、传感器、工单、轨迹、停车或铁路系统。
- 用户账号、角色权限、跨组织消息推送和真实身份认证。
- 多情景自由博弈、自动生成制度规则、自动绩效评价。
- 将模型输出写回案例正文或作为实证结论。

## 交接给编码人员的最小输入

1. 本启动包中的 `contracts/`、`data/`、`prompts/`、`eval/`。
2. 研究组签字或在台账中确认的证据卡清单。
3. AIfit 中 `artifacts/case_struct` 与 `artifacts/interview` 的只读参考路径。
4. Python 版本、端口、环境变量命名和离线运行约定。模型密钥只存在本地 `.env`，不进入仓库。
